Compare

What usually takes several systems

The search engines, the vector databases and the embedded databases each cover part of what an app with search and recommendations needs. Here is where Strata stands beside each of them, row by row, and below it, where they are ahead.

Elasticsearch is shown at its default Basic licence, which is what the cluster benchmark runs; paid tiers add RRF, linear fusion and more. Hover or tab to a mark for its detail.

Why one engine

One copy of each row, one planner, one structure

No pipelines to keep in step

A row's text, columns, vector and edges are written in one transaction and read from one snapshot. There is no second store to re-index, and no window where the search box and the database disagree.

Filters and rankings planned together

The planner sees the filter, the words, the vector and the graph walk of one statement, with exact counts per segment, so it can run the filter inside the vector search or fuse rankings under the same filter.

The laptop runs the cloud's structure

A shard is a Strata file. The file an app opens in-process, the server in front of it and the cluster on Kubernetes read the same format and answer the same SQL.

Where others are ahead

What Strata does not do as well, yet

A comparison that only lists wins is not one. These are the places to look before choosing Strata.

Elasticsearch and OpenSearch

Years of production at very large scale, an ecosystem around them (dashboards, ingest agents, security, alerting), analyzers for dozens of languages, and log analytics at petabyte scale.

Vespa

Proven serving at very large scale, tensor ranking with ONNX models in several phases, and a managed cloud. It is the fourth engine in the cluster benchmark for that reason.

Milvus, Qdrant and Weaviate

Indexes built for billions of vectors (on disk, on GPUs), more quantisation choices, and managed clouds. Strata has no vector index built for collections far larger than memory yet.

SQLite and PostgreSQL

Decades of hardening as general-purpose databases, and in SQLite's case a library that runs everywhere in a few hundred kilobytes. Strata loads 1.7–5.9× slower than SQLite when it builds an HNSW graph.

Tantivy

Faster facet counts on small collections (1.1–2.1× on three of four BEIR sets) and faster cold structured filters, where a range in Strata touches more pages.

Strata itself

A young project: English and simple analyzers only, no managed service, no point-in-time recovery between checkpoints yet, one writing process per file, and changes to the file format and cluster protocol still reviewed one by one.
