Where another system is clearly faster

The large losses, and what is being done about each.

Typo-tolerant search

10M · 81 ms on latest main; Elasticsearch 38

A misspelt word was expanded against the whole dictionary. #242 made it six to ten times faster (824 to 81 ms at 10M, 120 to 19.6 at 1M), but at 10M Elasticsearch and OpenSearch are still about twice as fast, and at 1M Typesense and Meilisearch take 6 ms.

SQL aggregates

10M · 2,894 ms on latest main; OpenSearch 4.08

A GROUP BY with HAVING over a filtered table. Strata's largest loss, and it grows with the data. Not fixed yet.

BM25 at 16 clients

10M · 470 q/s on latest main; OpenSearch 896

A query through a coordinator took two rounds to the shards. #245 made it one: at 1M Strata now serves 1,962 q/s, second to Qdrant's 2,471. At 10M the shards are what waits.

Key lookups

10M · 0.86 ms, 5th of 9; Postgres 0.37

Postgres, Weaviate, ParadeDB and Qdrant read a row by id in about half Strata's time.

Vector recall at shared settings

10M · recall@10 0.795; Qdrant 0.941

Strata scores 8-bit codes and re-scores the best 40, so read its vector speeds with this recall.

Short graph hops

Graph · 1 hop 0.35 ms over gRPC; Memgraph 0.18

Memgraph and FalkorDB, both in memory, answer one to three hops in about half Strata's time. Strata's own time on one hop is 0.10 ms against Memgraph's 0.02; gRPC instead of HTTP JSON took 0.1 ms off the rest. Not fixed yet.

Single-row writes in an app

One row a commit 4,022/s; SQLite 5,128

SQLite wins one row a commit; batches turn it around, 95,670 rows a second to SQLite's 18,905.

How we keep it fair

The same resources

Same CPUs, memory, data and vectors for every engine. In the latest runs, engines take turns on the same machines.

Answers checked

Recall@10 against exact search, and nDCG@10 where there are judgments.

Medians, not the best run

The median of three passes where there were three.

Every gap shown

A kind an engine cannot run counts as last place, and failed runs are reported.

Load not ranked

Strata's shards were built offline, so load times are shown but not ranked.

Reproducible

Scripts, settings, data hashes and raw results are all in the repository.

Questions

Are we biased?

Probably. We build Strata and wrote every engine's queries. Each engine runs at its defaults plus the tuning its documentation recommends, every setting is in the method, and we audited our own runs. If you know a better configuration, open an issue and we will run it again.

Why sum places instead of averaging speeds?

Latencies differ a thousandfold between kinds of query, so an average is decided by the slowest kind. Places weigh every test the same.

Doesn't counting a missing kind as last favour Strata?

It favours breadth, which a mixed workload needs. At 1M on latest main, Strata also leads on the seven kinds every engine runs; at 10M, on the older build, Postgres leads on the four every engine answered. Each report shows its ranking under five rules.

Why only nine engines at 10M?

Five did not run in 52 GiB. Milvus and Redis then ran with twice the memory: shown, not ranked.

Can I run it myself?

Yes: How we test has the commands for a laptop or a cloud account.
