Benchmarks

Measured on one laptop, against the tools each job uses today

Three ways Strata gets used: as one file inside an app, as a cluster on Kubernetes, and as the path between the two. Every system gets the same data, the same text analysis and the same vectors, and quality is reported beside speed, so nothing wins by answering worse.

Part A

One file in an app

A shop app whose database, search box and recommendations live in one file, measured as native processes on the laptop, one system at a time, warm and cold.

Part B

A cluster on Kubernetes, on the laptop

kind with three workers in Docker: two shards per engine on two workers, the client on the third, 3 CPUs and 6 GiB per engine as Kubernetes limits. Every node shares the laptop's CPUs, so the numbers compare the engines with each other, not with what any of them does on real machines.

Part C

Small to big, with the same answers

The shop's file and twelve of its queries, run at four stages. Each answer is checked against the first stage row by row, so the progression is shown to keep the results as well as the SQL.

How the numbers are taken

The machine

A MacBook Air with an Apple M2 (4 performance and 4 efficiency cores), 24 GB, macOS 26.0.1, with no fan. Part A runs native processes; Part B runs in Docker Desktop's VM (4 CPUs, 8.7 GB) with kind.

The rules

  • Power adapter in, Low Power Mode off, caffeinate on, other apps closed.
  • Each measurement runs three times in rotating order with a rest between systems, and the median run is reported. The laptop's thermal state is logged before each.
  • The same data, analysis (Snowball English with Lucene's stopwords) and vectors for every system. HNSW uses m 16 and ef_construction 200, and every system returns the top 10.
  • Each system at its defaults plus the tuning its own documentation recommends; the settings are committed with the results.

Reading the charts

  • Rows are kinds of query; columns are systems. Strata's bars are blue, every other system's grey.
  • Unless a chart says log scale, bars are scaled within their row, so each row compares the systems on that kind.
  • The best value in a row is bold. A star marks a value with a note, such as a raw-score sum standing in for normalised fusion.
  • "Not supported" means the system cannot run the kind. "App code" means it was run the way an app would write it.

Where the numbers live

The site reads every number from assets/bench-data.js. The runs write strata/results/laptop-2026-11/ and strata-server/results/laptop-2026-11/, each naming the machine; numbers are measured, never edited.
