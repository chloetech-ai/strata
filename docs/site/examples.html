Queries and examples

One shop, every kind of query

Everything here runs on one schema: the products of a game shop, its customers' reviews, and the items bought together. Each statement runs unchanged on the file in your program, on one server, and on a cluster; the badge under each says so.

The data

Three tables in one file

Products carry text, columns, a JSON object of the attributes no schema names, and a vector the database fills from the title and features as rows arrive. Reviews are placed by customer, so a customer's history stays on one shard. bought_with is a table and a graph at once.

CREATE TABLE products (
  id KEYWORD PRIMARY KEY, title TEXT, features TEXT,
  brand KEYWORD, category KEYWORD, platforms KEYWORD[],
  price FLOAT, rating FLOAT, ratings INT, in_stock BOOL DEFAULT TRUE,
  released TIMESTAMP, attrs JSON,
  emb VECTOR OPTIONS(embed = 'title, features', model = 'bge-small-en-v1.5')
);

CREATE TABLE reviews (
  id KEYWORD PRIMARY KEY, usr KEYWORD NOT NULL,
  item KEYWORD NOT NULL REFERENCES products,
  stars INT, body TEXT, ts TIMESTAMP
) OPTIONS(shard_by = 'usr', cluster_by = 'usr');

CREATE TABLE bought_with (
  id KEYWORD PRIMARY KEY,
  src KEYWORD NOT NULL REFERENCES products,
  dst KEYWORD NOT NULL REFERENCES products,
  w FLOAT DEFAULT 0
) OPTIONS(edges = 'src, dst, w');

A search box

Words, typos and synonyms

BM25 over the title, a tilde for "close enough", and the table's synonyms, under ordinary filters.

SELECT id, title, price, score() FROM products
WHERE MATCH(title, 'controler~ OR gamepad', synonyms => 1)
  AND price BETWEEN 20 AND 60 AND in_stock
ORDER BY bm25(title, 'controller gamepad') DESC LIMIT 10;

Facets beside the results

Aggregates run over any result, so the counts beside a search box are one more statement on the same snapshot.

SELECT brand, COUNT(*), AVG(rating), MIN(price) FROM products
WHERE MATCH(title, :q)
GROUP BY brand HAVING COUNT(*) >= 3 ORDER BY 2 DESC LIMIT 8;
fileservercluster

Autocomplete from what people searched

Each search counts itself into a table, and the box completes from it, forgiving a typo in what has been typed so far.

CREATE TABLE queries (id KEYWORD PRIMARY KEY, n INT DEFAULT 0) OPTIONS(cluster_by = 'id');

INSERT INTO queries (id, n) VALUES (:q, 1)
ON CONFLICT (id) DO UPDATE SET n = n + 1;

SELECT id, n FROM queries
WHERE PREFIX(id, :typed, fuzzy => 'auto')
ORDER BY n DESC, id LIMIT 8;

Vectors and hybrid

Search by meaning

The parameter is text; the database embeds it with the field's own model, so the app never handles a vector.

db.query("""SELECT id, title FROM products
            WHERE category = 'Accessories' AND price < 40
            ORDER BY similarity(emb, :v) DESC LIMIT 10""",
         v={"embed": "something to keep my console cool"})
fileserverclusterThe filter runs inside the vector search when it is selective, and after it when it is not; the planner counts which.

Words and meaning, fused

Two ways to combine the rankings: normalised scores with weights, or reciprocal rank fusion, which needs no weights.

-- weighted, on scores scaled to 0..1
SELECT id, title, score() FROM products WHERE in_stock
ORDER BY 0.5 * minmax(bm25(title, :q)) + 0.5 * minmax(similarity(emb, :v)) DESC LIMIT 10;

-- by rank, with no weights to tune
SELECT id, title, score() FROM products WHERE in_stock
ORDER BY rrf(bm25(title, :q), similarity(emb, :v)) DESC LIMIT 10;
fileserverclusterFusion: rrf, minmax, tmm, zscore

More like this one

-- :v = {"vector_of": "B07XYZ", "field": "emb"}
SELECT id, title FROM products WHERE id != 'B07XYZ'
ORDER BY similarity(emb, :v) DESC LIMIT 10;

Ranking

Any expression of scores and columns

Relevance, rating and age in one order, with no plugin or script language.

SELECT id, title, score() FROM products WHERE MATCH(title, :q)
ORDER BY ln(1 + bm25(title, :q)) * (1 + 0.2 * coalesce(rating, 0))
       + decay(released, now(), 2592000) DESC LIMIT 10;
fileservercluster

A cheap first phase, then a reranker

The first phase keeps a hundred rows; a cross-encoder reads each with the query and orders the ten that are shown.

WITH top AS (
  SELECT * FROM products
  ORDER BY rrf(bm25(title, :q), similarity(emb, :v)) DESC LIMIT 100
)
SELECT id, title, score() FROM top
ORDER BY cross_encoder('ms-marco-MiniLM-L-6-v2', title, features, :q) DESC LIMIT 10;

A ranking with a name

Kept in the database, so the app asks for "the shop's ranking" and the people who tune it change it in one place.

CREATE RANK PROFILE shop ON products AS
  WITH top AS (SELECT * FROM products ORDER BY bm25(title, :q) DESC LIMIT 200)
  SELECT * FROM top ORDER BY bm25(title, :q) * (1 + :pop * ln(1 + ratings)) DESC
  WITH (pop => 0.1);

SELECT id, title FROM products WHERE in_stock
ORDER BY rank_profile('shop', q => :q) LIMIT 10;

Suggesting

Recommendations

The same statement reads a customer's history and ranks the catalogue by it, so a recommendation is a query, not a pipeline.

What this customer will want next

encode runs a sequence model over the customer's last reviews and returns a vector; the products nearest it come back, at most two of a brand.

SELECT id, title, brand FROM products WHERE in_stock
ORDER BY similarity(emb, encode('next',
  (SELECT item, ts FROM reviews WHERE usr = :u ORDER BY ts DESC LIMIT 200)))
DESC MAX 2 PER brand LIMIT 10;
fileserverclusterTraining the sequence model

Bought together, walked from the basket

Personalised PageRank over bought_with, started from the items the customer reviewed last.

SELECT id, title, score() FROM products WHERE in_stock
ORDER BY ppr(bought_with,
  (SELECT item FROM reviews WHERE usr = :u ORDER BY ts DESC LIMIT 20)) DESC LIMIT 10;
fileservercluster

All three signals at once

SELECT id, title FROM products WHERE in_stock AND MATCH(title, :q)
ORDER BY rrf(
  bm25(title, :q),
  similarity(emb, encode('next', (SELECT item, ts FROM reviews WHERE usr = :u ORDER BY ts DESC LIMIT 200))),
  ppr(bought_with, (SELECT item FROM reviews WHERE usr = :u ORDER BY ts DESC LIMIT 20))
) DESC MAX 2 PER brand LIMIT 10;

Analytics, JSON and plain SQL

A join with aggregates

SELECT p.brand, COUNT(*) AS reviews, AVG(r.stars) AS stars
FROM reviews r JOIN products p ON r.item = p.id
WHERE r.ts >= '2026-01-01'
GROUP BY p.brand ORDER BY reviews DESC LIMIT 10;

Keys no schema names

Paths into a JSON column are indexed as they arrive; json_paths lists what has been seen.

SELECT id, title, attrs.dims.w FROM products
WHERE attrs.voltage >= 5 AND attrs.certs = 'UL'
ORDER BY attrs.dims.w DESC LIMIT 10;

SELECT * FROM json_paths('products', 'attrs');

Everything else

Data in and out

A SQLite file comes in as tables with their types and keys, and any table goes back out as one.

From SQLite

strata-server import --db shop.strata shop.sqlite        # a new file from SQLite's tables
curl -s -X POST 'localhost:7700/v1/import?format=sqlite&plan=true' \
  -H 'content-type: application/vnd.sqlite3' --data-binary @shop.sqlite   # what it would make
curl -s 'localhost:7700/v1/export' -o copy.sqlite            # and back out

Everything else

The same query from every client

In-process and over the network take the same SQL and the same parameters, and the Python client has the same methods as the embedded database.

import strata

db = strata.open("shop.strata")
rows = db.query(
    "SELECT id, title FROM products WHERE in_stock "
    "ORDER BY rrf(bm25(title, :q), similarity(emb, :v)) DESC LIMIT 10",
    q="wireless controller", v={"embed": "wireless controller"}).rows
import strata

db = strata.connect("http://127.0.0.1:7700")   # one server, or a cluster's coordinator
rows = db.query(
    "SELECT id, title FROM products WHERE in_stock "
    "ORDER BY rrf(bm25(title, :q), similarity(emb, :v)) DESC LIMIT 10",
    q="wireless controller", v={"embed": "wireless controller"}).rows
curl -s localhost:7700/v1/query -H 'content-type: application/json' -d '{
  "sql": "SELECT id, title FROM products WHERE in_stock ORDER BY rrf(bm25(title, :q), similarity(emb, :v)) DESC LIMIT 10",
  "params": {"q": "wireless controller", "v": {"embed": "wireless controller", "field": "emb"}}
}'
use std::path::Path;
use strata::{db::Db, query::Params, storage::DbOptions, value::Value};

let db = Db::open(Path::new("shop.strata"), DbOptions::default())?;
let q = Value::Str("wireless controller".into());
let rs = db.query(
    "SELECT id, title FROM products WHERE MATCH(title, :q) ORDER BY bm25(title, :q) DESC LIMIT 10",
    &Params::new().set("q", q),
)?;
for row in &rs.rows { println!("{row:?}"); }
strata shop.strata "SELECT id, title FROM products WHERE MATCH(title, 'wireless controller') LIMIT 10"
