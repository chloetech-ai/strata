Features

Search, data and recommendations in one engine

Every table is indexed four ways over the same rows: full text, columns, vectors and graph edges. One SQL statement can use them all.

Full textColumns and JSONVectorsGraphsRankingRecommendationsSQL and storageAPIs and clientsData inOn the deviceClusterOperations

Full text

Posting lists scored with BM25, with typos, synonyms and autocomplete.

Full-text queries
  • BM25 and boolean queriesAND, OR, NOT, phrases and groups, with top-k skipping.
  • Weighted wordsWord weights, required and excluded words, "x of y" groups.
  • Typos and synonymsvacine~ finds words within an edit or two.
  • AutocompletePrefixes that tolerate typos, over a sorted dictionary.
  • Our own posting listsThe size of Elias-Fano, and 2.4–7.7× faster. The study
  • Versioned analyzersA field records its analyzer, so text is never misread.

Columns and JSON

Typed columns for filters, ranges and facets, and JSON for keys nobody declared.

Tables
  • Typed columnsKeywords, numbers, booleans, times and lists, with constraints.
  • Filters and facetsRange scans over zone maps, and GROUP BY for facet counts.
  • JSON fieldsFilter, group and sort by any path, read from the index.
  • Text inside JSONEvery string in an object searchable and ranked.
  • Schema changes while servingALTER TABLE on a database, its replicas and a cluster.
  • Rows that expireA time to live per row, for caches and sessions.
  • Percentiles and datesMEDIAN, PERCENTILE_CONT, date_trunc, EXTRACT and strftime.
  • Fields a model writesA summary, a category or a product name, written by Claude or your own model when the row is.

Vectors

Approximate and exact search, under any filter, fused with text.

Vector indexes
  • HNSW, IVF or exactWith 8-bit, binary or RaBitQ codes.
  • Filtered search, plannedThe planner picks a strategy per segment from exact counts.
  • Partitioned graphsA graph per value or range of a column, so a filtered search walks only its own.
  • Hybrid fusionrrf() or weighted sums over text, vectors, graphs and columns.
  • Multi-vector MaxSimLate interaction, as ColBERT and ColPali score it.
  • Sparse vectorsLearned weights such as SPLADE.
  • Embeddings on writeLocal models, or OpenAI, Cohere, Voyage, Gemini and others.
  • Images and soundMedia embedded with SigLIP and CLAP, in one space with text (a server built with the vision and audio features).

Graphs

Edges stored with the rows, walked inside a query.

Graphs
  • Edges in rows or tablesAn edge field on a row, or an edge table with properties.
  • Reachability and pathsREACHABLE and shortest paths, in either direction.
  • PageRank as a scorePersonalised PageRank seeded by any query.
  • Similarity as edgesA row's neighbours are its most similar rows.

Ranking

From a formula to a learned model, with the evidence to choose between them.

Ranking
  • Ranking expressionsAny expression of scores and columns.
  • Rerank phasesA cheap first phase, then a costly one on the top rows.
  • Rank profilesA named ranking with parameters.
  • LightGBM and XGBoostTree models scored in the query.
  • Cross-encodersRerank with a model that reads query and row together: a hosted one, or a local one in a server built with bert.
  • Rank log and interleavingWhat each query served, interleaving, and judgments.

Recommendations

Models and rules in the same query as search.

Sequence models
  • Sequence modelsEncode a user's history and rank what comes next.
  • Counted next itemsWhat came after what, counted and decayed in place.
  • Semantic IDsItems as codes a generative model can produce.
  • Rules in the rankingAt most two per brand, in stock, not yet bought.
  • EvaluationA recommender gate in CI, and an evaluation view.

SQL and storage

A real database: SQL, transactions and one file you can copy.

Query language
  • SQLJoins, subqueries, window functions and set operations.
  • DataFusion for large plansBig joins and groups run on DataFusion.
  • ACID transactionsSnapshot isolation and shadow-paged commits.
  • Key-value readsGet, put and delete by key without SQL.
  • One file, many tablesCopy it, back it up, open it anywhere.
  • User-defined functions (UDFs)CREATE FUNCTION keeps a score, a value or a whole query (a table function) in the database, versioned, for any query to call.
  • Samples and splitsThe same sample, train/test split or shuffle every time, with hash().
  • ScrollsRead a large answer a page at a time, on one server or across shards.
  • Many writers, many readersConcurrent writes share commits; other processes read while one writes.
  • Older segments on S3Kept on object storage and read through a local cache.

APIs and clients

The same methods in your process or over the network, and the APIs other systems speak.

Server
  • HTTP JSON and gRPCAPI keys, TLS, an audit log and limits.
  • The OpenSearch APIApps and clients written for OpenSearch or Elasticsearch index and search unchanged. How
  • PythonIn-process or a client, with Arrow, pandas and polars.
  • DataFramesFrames written as Polars writes them, run as one SQL query, answered in Arrow.
  • JavaScriptNode, Bun and Deno, prebuilt for four platforms.
  • Java and JDBCA JNI library and a jdbc:chloedb: driver.
  • Rust and the shellThe engine as a crate, and a command line.
  • Agents over MCPClaude Code and other agents list tables, query and write.
  • An agentAsk in English, get an answer in SQL.

Data in

Bring the rows from where they already live, and keep them in step.

Following Postgres
  • Follows PostgresTables kept in step by logical replication, each change applied once.
  • SQLite and ParquetIn and out; Parquet from local files or S3, as Spark writes it.
  • OpenTelemetry logsCollectors and SDKs send their logs in over OTLP.
  • A crawlerGive it a site: it makes a table, fills it and adds shards as it grows.

On the device

A slice of a table near the user, searched on the phone, with the server as fallback.

Slices
  • Geo slicesThe places near a user, in tiles, scored as the server would score them.
  • Vector slices"More like this" and recommendations from the rows nearest in meaning.
  • Proved, or askedThe device answers when it can prove the server's answer, and asks the server otherwise.
  • Python and JavaScriptHelpers that fetch tiles as the user moves, and report what they answered.

Cluster

Shards and replicas behind a coordinator, managed on Kubernetes.

Laptop to cloud
  • Shards and a coordinatorOne database to clients, many machines behind it.
  • Data moves while servingSlots move between shards without downtime.
  • Replicas and failoverA new primary is elected when one dies.
  • Writes applied onceRetried writes and stream events apply once, through failovers and slot moves.
  • Follow another clusterA second cluster a moment behind, and a planned switch-over that loses no write.
  • Kubernetes operatorUpgrades one copy at a time, autoscaling, a published image.

Operations

Broken on purpose before it breaks in production, and an agent on call.

The command center
  • A deterministic simulatorFailover and slot moves replayed from a seed under crashes.
  • A chaos monkeyCrashes, stalls, partitions and full disks on a real cluster, every night.
  • Damaged data caughtEvery segment read against its checksum while serving, and an alert when one fails.
  • An on-call agentClaude looks into an alert and proposes a fix; an admin approves it.
  • A Simulator in the consoleTest-runs the cluster, grades it, and predicts what other shapes would hold and cost.
  • A command centerEvery server ships a console. Tour it
