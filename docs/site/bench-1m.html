Cluster · 1M passages · DigitalOcean · 4 to 6 November 2026

Fourteen engines, 1M passages, latest main

Strata on main of 6 November against thirteen engines, with the same data, the same 14 kinds of query and three passes each. Each engine's numbers come from its newest run: an engine whose code or settings changed ran again, the others kept their 4 November numbers. Engines that shard had two 4-vCPU machines, the others one 8-vCPU machine, with the same CPU limit.

Strata is first under all five ranking rules. It runs all 14 kinds, is in the top half on 42 of 45 tests and is never below 10th. It is fastest outright on 9 tests: the three of SQL aggregates, both hybrids at one and four clients, prefix queries and the 99th percentile of facets. Qdrant is faster on BM25, Typesense and Meilisearch on typos, and Redis on key lookups and vectors.

Writes and streams

Searchable in 8 ms, and a stream written once

Strata and Vespa make a write searchable when it returns (7.6 and 8.6 ms); Elasticsearch, OpenSearch and Solr refresh every second. Single inserts are about as fast as Elasticsearch's and OpenSearch's, and Solr's are faster up to four clients. At 16 clients Strata's updates are more than twice as fast as any other's, because it sets one column in place. From one client, Strata's writes are slower than on 4 November (287 inserts a second against 417, 285 updates against 547): other nodes, and a coordinator now across the network; the run did not separate the two. After a consumer crash, Strata resumes exactly, since offsets commit with the rows; the others write some events twice. None lost any.

Load and size

Shown, not ranked

Strata's shards were built offline from local files, the others over HTTP, so load times do not compare.

Where Strata is behind

Three kinds where it is clearly slower

  • Typo search. 13.1 ms, down from 120 in the first run (#242, #266); Typesense and Meilisearch take 6.0, Elasticsearch 14.7.
  • Key lookups. 0.89 ms through Strata's key API and a coordinator, 9th of 14; Redis takes 0.09 and Postgres 0.21.
  • BM25 × recency. 4.18 ms, 4th; Qdrant takes 1.95. Plain BM25 is 3rd at 2.03 ms, behind Qdrant's 1.63.
Since the first run

SQL aggregates 21 times faster, typos nine times, BM25 76% more at 16 clients

Strata's medians in the first 1M run (3 November) and on main of 6 November. The coordinator caches each shard version's term statistics (#245), so a BM25 query takes one round to the shards instead of two; a misspelt word is no longer expanded against the whole dictionary (#242, #266); aggregates read their groups from the columns (#252, #264); and later BM25 segments start at the scores the earlier ones found (#258). The machines changed too: Elasticsearch's BM25 median went from to ms, OpenSearch's from to . One-client latency also pays the network hop to a coordinator in a shard's pod (#287), which the first run's coordinator, on the client's machine, did not.
