Cluster · 1M passages · DigitalOcean · 4 November 2026

Fourteen engines, 1M passages, latest main

Strata on latest main, with the BM25 and typo fixes, against thirteen engines. The engines of each lane took turns on the same DigitalOcean machines, with the same data, the same 14 kinds of query and three passes. Engines that shard shared two machines, the others one, with the same CPU limit.

Strata is first under all five ranking rules. It runs all 14 kinds, is in the top half on 40 of 45 tests and is never below 11th. It is fastest outright on 8 tests: facets, both hybrids, and the 99th percentile of filtered vectors and similar items. Qdrant is faster on BM25, Typesense and Meilisearch on typos, Redis on key lookups, and OpenSearch and Elasticsearch on SQL aggregates.

Data
1M MS MARCO v2.1 passages, with their Arctic Embed M v1.5 vectors (768 dimensions)
Machines
DigitalOcean sfo2: two 4-vCPU nodes taken in turn by the five engines that shard, one 8-vCPU node by the other nine

Writes and streams

Searchable in 5 ms, and a stream written once

Strata and Vespa make a write searchable when it returns (5.4 and 8.6 ms); Elasticsearch, OpenSearch and Solr refresh every second. Single inserts are about as fast as the Lucene engines'. Updates are more than twice as fast, because Strata sets one column in place. After a consumer crash, Strata resumes exactly, since offsets commit with the rows; the others write some events twice. None lost any.

Load and size

Shown, not ranked

Strata's shards were built offline from local files, the others over HTTP, so load times do not compare.

Where Strata is behind

Three kinds where it is clearly slower

  • Typo search. 19.6 ms with #242, down from 120 in the first run; Typesense and Meilisearch take 6.0, Elasticsearch 14.7.
  • SQL aggregates. 184 ms through a coordinator, where OpenSearch and Elasticsearch take 4.7 and 6.4, likely from their request cache, which the run left on for SQL (our audit). In review: #252 reads the groups from the columns, 722 to 27 ms for this query on 5M rows in a container.
  • Key lookups. 0.79 ms through Strata's key API and a coordinator, 9th of 14; Redis takes 0.09 and Postgres 0.21.
Since the first run

BM25 74% faster at 16 clients, typos six times faster

Strata's medians in the first 1M run (3 November) and in this one. The coordinator now caches each shard version's term statistics (#245), so a BM25 query takes one round to the shards instead of two, and a misspelt word is no longer expanded against the whole dictionary (#242). SQL aggregates did not get faster. The machines changed too, and were if anything slower: Elasticsearch's BM25 median went from to ms, OpenSearch's from to . Both builds on the same nodes, BM25 at 16 clients gained 30% (results).
