Search inside an app

A store, a notes app or a help center: typos, facets and hybrid search on the rows the app already keeps, with no second service.

Replaces
SQLite with FTS5, or a database plus Elasticsearch
Measured
Hybrid search 1.9–17× faster than SQLite, DuckDB or LanceDB with each on one thread, 4.8–33× with ChloeDB on up to eight (no server)
SELECT id, title, price, score() FROM products
WHERE MATCH(title, :q, synonyms => 1) AND in_stock
ORDER BY rrf(bm25(title, :q), similarity(emb, :v)) DESC LIMIT 10;

SELECT brand, COUNT(*) FROM products WHERE MATCH(title, :q)
GROUP BY brand ORDER BY 2 DESC LIMIT 8;

Recommendations

"Next for you", "bought together" and "more like this", ranked from the customer's history at the moment they ask.

Replaces
A vector database, a feature store and nightly batch jobs
Measured
MovieLens 1M Recall@10: 0.306 with encode, 0.242 with ppr
SELECT id, title FROM products WHERE in_stock
ORDER BY rrf(
  similarity(emb, encode('next',
    (SELECT item, ts FROM reviews WHERE usr = :u ORDER BY ts DESC LIMIT 200))),
  ppr(bought_with,
    (SELECT item FROM reviews WHERE usr = :u ORDER BY ts DESC LIMIT 20))
) DESC MAX 2 PER brand LIMIT 10;

Sessions, carts and caches

Rows read by key on every request, in the same database, each with its own time to live.

Replaces
A key-value store or cache beside the database
Measured
21 µs a read inside an app; 0.99 ms through a coordinator at 10M (behind Postgres)
curl -s -X PUT localhost:7700/v1/kv/sessions/s1 -H 'content-type: application/json' \
  -d '{"usr": "u7", "until": "2026-11-02T12:00:00Z"}'
curl -s localhost:7700/v1/kv/sessions/s1
curl -s localhost:7700/v1/kv/get -H 'content-type: application/json' \
  -d '{"table": "sessions", "keys": ["s1", "s2"]}'

Retrieval for agents

Words for names and codes, vectors for meaning, a reranker for the top rows, and filters for who may see what. Agents such as Claude Code reach it over MCP, and stored functions keep the retrieval query in one place.

Replaces
A vector database, a keyword index and a reranking service
Needs
For a local cross-encoder, a server built with --features bert; hosted rerankers (Cohere, Voyage, Jina) need only a key
Measured
Hybrid search fastest of nine engines at 10M passages (10M)
WITH top AS (
  SELECT * FROM passages WHERE team = :team
  ORDER BY rrf(bm25(body, :q), similarity(emb, :v)) DESC LIMIT 20
)
SELECT id, doc, body FROM top
ORDER BY cross_encoder('bge-reranker-base', body, :q) DESC LIMIT 8;

Photos, sound and video

A file is a column. Images are captioned and embedded on write, so words find a picture and a picture finds its neighbours.

Replaces
A captioning job and a vector database
Needs
A server built with --features vision (images) or audio (sound): the release archives and the image leave them out
CREATE TABLE shots (
  id KEYWORD PRIMARY KEY, item KEYWORD REFERENCES products,
  image MEDIA OPTIONS(kind = 'image'),
  caption TEXT OPTIONS(derive = 'image', model = 'blip-image-captioning-base'),
  emb VECTOR OPTIONS(embed = 'image', model = 'siglip-base-patch16-224')
);

SELECT DISTINCT ON (item) item, id, image FROM shots
ORDER BY rrf(bm25(caption, :q), similarity(emb, :v)) DESC LIMIT 12;

Search over your Postgres

The app keeps writing to Postgres. ChloeDB copies the tables of a publication, then applies every change a moment after it commits, each once, so search, vectors and facets run on the same rows.

Replaces
Debezium, Kafka and a sync job into a search engine
Read
Following Postgres
chloedb-server follow-postgres \
  --source 'postgres://chloedb:...@db.example:5432/shop' \
  --target http://localhost:7700 --name shop

curl -s localhost:7700/v1/sql -H 'content-type: application/json' -d '{"params": {"q": "trail shoes"},
  "sql": "SELECT id, title FROM products WHERE MATCH(title, :q) LIMIT 10"}'

Near me, on the phone

The app keeps a slice of the places around its user and searches it on the device, scored as the server scores them. When it cannot prove its answer is the server's, it asks the server.

Replaces
A search request on every keystroke, and a separate offline index
Read
Slices
import chloedb

near = chloedb.nearby("https://api.example", "places", "./slice")
near.move_to(40.7484, -73.9857)   # fetches the tiles around the user
r = near.search("pizza", k=10, d0=1000)
print(r.where, r.why)             # "device" or "server", and why
for row in r:
    print(row["name"])

Logs and queries

An OpenTelemetry Collector or SDK sends application logs straight in over OTLP, and ChloeDB keeps its own logs and every query it answers the same way. Finding why a service failed is a SQL search, with older data on S3.

Replaces
A log search cluster behind the Collector
Read
OpenTelemetry logs
SELECT ts, service, severity, body FROM otel_logs
WHERE severity IN ('ERROR', 'FATAL') AND MATCH(body, 'timeout OR refused')
  AND ts > '2026-11-08T06:00:00Z'
ORDER BY ts DESC LIMIT 100;

SELECT service, COUNT(*) FROM otel_logs
WHERE attributes['http.status_code'] >= 500 GROUP BY service;

Knowledge graphs

Edges are rows, written in the same transaction as the documents they link, and a walk can start from a search.

Replaces
A graph database beside the search index
Measured
1st of 5 against four graph databases on summed places, on one laptop; 21 against Memgraph's 24 without PageRank, and about twice Memgraph's and FalkorDB's time on one to three hops (graph)
-- the papers two citations from the closest matches
SELECT id, title, hops() FROM papers
WHERE REACHABLE(cites,
  (SELECT id FROM papers ORDER BY similarity(emb, :q) DESC LIMIT 3),
  hops => 2, dir => 'both')
ORDER BY hops(), id LIMIT 20;
