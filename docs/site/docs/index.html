ChloeDB is an embedded search database with SQL: full text, structured columns, vectors and graph edges over the same rows, in one file, combined in one query by one planner. It runs inside your program like SQLite, or as a server and a cluster with the same SQL.

QuickstartInstall it and run your first search in five minutes. ConceptsThe file, tables, the three indexes, scores and the planner. Search guideWords, typos, filters, facets, vectors and hybrid ranking, on one small catalogue. SQL referenceEvery statement, function and option.

Cookbook#

Complete programs for common jobs. Each one runs, as written, every time the code changes.

Retrieval for RAGChunk documents, search them by words and meaning, and hand a model the passages with their sources. Memory for an agentRemember turns and facts, recall what matters to a new message, and keep facts current. Crawl a site into searchPoint the crawler at a site, get a table with its fields, and search it. Search your logsSend syslog and OpenTelemetry logs to a table, and find the last 15 minutes' errors, a flapping interface, an IP.

Use it from#
Python import chloedb: a database in your process, or a client of a server, with the same methods; DataFrames too
JavaScript Node, Bun and Deno in-process, or a fetch client for any runtime
Java in-process over JNI, and a JDBC driver
HTTP and gRPC chloedb-server, its command center, and a cluster of them

Apps#

Apps on a cluster run beside chloedb-server and show in its command center: the crawler, Sheets and ChloeCtx, memory for Claude Code.

How these pages are tested#

The guide and cookbook pages are run as scripts: docs/guide/run.py runs every code block on a page, in order, in an empty directory, against the programs built from the same commit, and checks the output shown under a block against what it printed. A page that says so at its top has passed. The reference pages (SQL, server, clients, apps) are rendered from the Markdown in docs/chloedb/ and docs/chloectx/.
