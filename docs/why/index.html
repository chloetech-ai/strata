Long-term memory for Claude Code

Keep every session. Re-read only what matters.

Engram records every session of a project on your machine, without a model call, and at each prompt hands the agent the few thousand tokens that answer it. On 208 coding follow-ups it solved as many tasks as keeping the whole history in context, for about a quarter of the cost per run.

Where it wins

On coding work it beats every memory system we ran

Four projects, each built over a recorded history of sessions; in one, a teammate's commits land in between. Then 52 follow-up tasks, most of which need something only said in an earlier session: a decision, a customer's rule, a changed convention. Each memory system ran every task four times in a new session, with the same agent, and a script graded the result.

12–14 of 16

It catches what a request implies

A task asks to enter a school's order with Bakewell slices. Months earlier the history says the school is nut-free, and the catalog lists nuts in the slice. The new builds left the slice out in 11 of 12 runs and said why. On these 16 runs: previous release 8, whole history 10, mem0 1.

$0 to store

It pays per question, not per history

Engram stores raw records without a model call. Hindsight spent about $1.00 of model calls per LongMemEval history and mem0 $0.13. Engram's query engine spends $0.0012 a question, in the background, and in Claude Code its distiller about $0.001 a turn (counted in the costs above).

79.0% · 43.1

Level or ahead at the same context size

Same reader, judge and questions, with 1,600 to 4,900 characters of context each: on LongMemEval-S and BEAM 100K, mem0 scores 79.0% and 41.9, Hindsight 78.0% and 39.8. Engram also declines what it cannot answer more often: BEAM abstention 73.8 against Hindsight's 62.5.

81.8%

LongMemEval-S, up from 72.2%

On all 500 questions, adding the query engine's picks to plain search gains 9.6 points (p = 10−8). The same reader given only the sessions that hold the answer reaches 89.8%, so the gap left is 8 points.

35.7 at 1M

It holds up over a million tokens

BEAM at 100K, 500K and 1M tokens: 43.2, 40.2 and 35.7, against 36.3, 33.5 and 32.2 for plain search and about 10 with no memory. The BEAM paper's best method reports 35.8, 35.9 and 33.6, with a different reader.

5.7 ms

Fast enough to run on every prompt

A recall query over a million records takes 5.7 ms at the median on an M2 MacBook Air, and the file holds 3.1 KB a record. The prompt hook takes 17 ms at that size in the cloud container.

How it searches

Every kind of search, and a planner that picks among them

Engram runs on Strata, an embedded search database built alongside it. One file per project indexes every record as full text, structured fields, vectors and a graph at once, and one SQL statement can combine them. For each request, Engram decides which searches are worth running and how to run each one.

Full text

BM25 ranking with Block-Max WAND, plus boolean and phrase queries.

Finds the exact error message or function name.
Semantic

Embeddings from a small local model, searched with an HNSW vector index.

Finds the same idea said in other words.
Hybrid

Keyword and vector rankings mixed into one list, weighted by kind and age.

What runs on every prompt.
Structured

SQL filters and facets over session, kind, time, files and importance.

"Decisions from last week that touch billing.py."
Graph

Notes link to what they are about, such as a customer or a file, and the search walks to their neighbours.

On citation search, Strata's graph doubled what vectors found: nDCG@20 0.123 to 0.253.
  1. Plan. A small model reads the request and writes up to eight searches across those kinds: keywords for a name, a sentence phrased like the record it hopes to find, a SQL filter for a time range, the graph around a customer.
  2. Run. Strata's cost-based planner picks how to evaluate each search from exact statistics. A filtered vector search becomes an exact scan, IVF, HNSW with the filter inside, or post-filtering, whichever is cheapest for that filter near that query.
  3. Pick. A second call keeps only what answers the request: 2.8 records and 960 characters on average, which hold all the evidence for 76% of LongMemEval questions.

Fast and small because it works on bits

Every index is a compact structure read in place through mmap, with nothing to deserialise. Posting lists use Loom and Pyramid, two formats designed for Strata that line dense runs of documents up on machine words. Columns are bit-packed in 128-document blocks with min/max zone maps, filters probe bitsets of accepted values in 4 to 5 ns, and vectors are scanned as 8-bit codes with SIMD integer dot products.

1.7–3.2×faster BM25 top-10 than Tantivy, and 43–200× faster than SQLite's FTS5.
0.05–0.10 msfor a vector top-10 with HNSW. SQLite scanning the same vectors takes 7.7 ms to 0.7 s.
1.8–6.1×faster filtered vector search than the best fixed strategy, by choosing per query, at recall@10 0.991–0.998.
2.4–3.0×faster conjunctions than partitioned Elias-Fano at the same size, and 3.8–7.7× faster unions (Loom).
12.2–12.7 bitsper posting, docID and frequency included. The TREC-COVID text index is 44.5 MiB, against 60.0 for Tantivy and 70.0 for FTS5.
14 nsper 1,024-dimension dot product on 8-bit codes with NEON, reading 4× less than float32.

Measured on the M2 MacBook Air with Strata's BEIR benchmarks. Where it is slower: building the HNSW graph makes loading 1.7–5.9× slower than SQLite, Tantivy counts facets 1.1–2.1× faster on three of four collections, and Tantivy's cold structured filters are 1.4–3.4× faster. Details are in Strata's results and the posting-list study.

Where it loses

What it does not do well yet

These are measured too, in the same runs. Most come down to one thing: Engram picks a few records per question, so anything that needs many messages at once, or a second search, suffers.

−9.0

Hindsight at full budget scores higher

88.0% against 79.0% on LongMemEval-S (p = 0.02) and 46.7 against 43.1 on BEAM (p = 0.09). It hands the reader 38 to 75 times more text, near what the whole history scores, after about $1 of model calls per history.

17%

Questions that chain two facts

When one answer says what to look up next ("the citizenship of X's spouse"), Engram answers 17% and the whole history in context 71%. A second round of searches is the missing step.

17.0

Answers spread over many messages

BEAM summaries: Engram 17.0, Hindsight 37.5, the whole history 40 on a sample. Contradiction resolution stays at 14 to 26 at every history length.

40 vs 56

Facts that were overwritten

mem0 rewrites facts when it stores them and does better on BEAM's knowledge updates: 56 against 40. Engram stores the raw record and has to find the latest one.

43/400

The planner can skip memory

On FactConsolidation it judged 43 of 400 questions to be general knowledge ("What is the capital of Japan?") and searched nothing, in a benchmark whose facts are deliberately counterfactual: 85.3% against 95.5% for plain search. In Claude Code the per-prompt recall still runs beside it.

59%

The injection gate is imprecise

59% of its injections hold evidence (42% when always injecting). In a multi-day test it skipped the prompts where a compaction had dropped a fact, so it brought nothing back: 27 of 30 against 26 with compaction alone.

91–95%

Vendors report higher scores

On LongMemEval-S, OMEGA reports 95.4%, Mastra 94.9%, Hindsight 91.4%; on BEAM 100K, Exabase 76.9 and Hindsight 73.4. These are self-reported, with bigger answer models than Haiku, and we have not reproduced them. In our harness Hindsight scored 88.0% and 46.7.

p = 0.25

The evidence has limits

The coding test is four projects we wrote, with one agent model. The new build is level with the previous release overall (196 to 201 of 208 against 195); its gain is on requirements a request implies.

What it saves

Replace a big context with a small one

Every model call in a coding session re-reads everything in context: a long session kept alive for its history, or docs and old transcripts pasted in. Engram lets that context go and injects about 3,100 tokens per prompt instead. On Haiku 5.5 a call whose prompt is over 100,000 tokens pays five times the rate on every token, output included, so the big context also raises the cost of the rest of the session.

Measured, not estimated

In the coding test above (Haiku agent, cloud container), a run with the whole history in context cost $0.016 while the history was in the prompt cache and about $0.07 when it was not. Engram's shipped build cost $0.0087 a run, its own model calls included, and solved 196 runs to the whole history's 194.

On a Claude subscription the same tokens count against your usage limits instead of a bill.

  • Engram's injection: 3,100 tokens a prompt, its mean in the coding test. Its own model calls: $0.0019 a prompt (distiller and query engine on Haiku), measured there.
  • The percentage saved on the context alone is about the ratio of tokens, whatever the price or the cache rate.
  • Quality held on coding follow-ups. On chat questions that need many messages at once, the whole history still answers more (see the losses above).
  • Prices: Anthropic's list prices, read 2026-10-17. Cache reads are 0.05× input on Opus 5.5 and Sonnet 5.5 and 0.025× on Fable 5.1.

Install

One command, and every new Claude Code session remembers

Engram plugs into Claude Code's own hooks and MCP, so nothing changes in how you work. One script builds it, downloads its 129 MB embedding model, wires it into Claude Code for every session or for one project, and checks the result.

Run it yourself

git clone https://github.com/rkonow/engram
cd engram && ./install.sh
# or only for one project:
./install.sh --project ~/code/app

It needs macOS or Linux (Windows through WSL 2), Rust, a C compiler, curl and the Claude Code CLI logged in. The first build takes a few minutes. Run it again after git pull to upgrade. The install guide covers remote machines, dev containers and troubleshooting.

Or ask Claude Code to do it

Clone https://github.com/rkonow/engram and set Engram up for my Claude Code by following its AGENTS.md.

Paste it into any session. The agent checks the prerequisites without installing anything unasked, asks whether you want every session or one project, runs the installer and reports anything that failed.

Nothing to remember to save

Every prompt, tool call, error and answer is recorded by the hooks. A new session starts out knowing what earlier sessions decided.

It stays on your machine

One store file per project under ~/.local/share/engram/projects/. Its only model calls are Haiku, through your own Claude Code login.

Checked, visible, reversible

engram doctor checks every piece and says how to fix what fails. engram ui shows what was stored. engram uninstall --user removes it and keeps the stores.

Measured 2026-10-15 and 2026-10-16 in a cloud container (4 CPUs, 16 GB), except where a number names the M2 MacBook Air. Haiku is the agent, reader and judge throughout. The cost figures in the calculator are estimates; everything else on this page is measured.
