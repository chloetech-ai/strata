Engram works as a long-term memory for Claude Code. Every hook event is stored without the model's help. The details compaction throws away come back when a prompt asks for them, and a new session starts out knowing what earlier sessions decided. Its weak point is the decision to inject: the gate keeps costs down but cannot reliably tell a related record from a relevant one.

Store without being asked

Met: prompts, tool calls and results, errors, answers, the commentary between tool calls, and compaction summaries are all captured from hooks. A hook costs 9–17 ms, appends take under 1.5 ms, and nothing blocks when the daemon is down. The 26-hour session becomes 2,204 records, back-filled in 6 seconds.

Missed: the model's reasoning is redacted in transcripts, so the "why" survives only where it was written out. Commentary capture reads Claude Code's transcript, whose format is internal.

Load without being asked, only when it helps

Met: after a compaction, 13 of 15 lost details came back automatically. Live sessions answered all eight questions about this repository's 26-hour history, against none of four with Engram off. Nothing still in the context window is repeated, and answers that admitted not knowing are not replayed.

Missed: the gate's precision is modest: 59% against 42% for always injecting on LongMemEval, with no gain on LoCoMo. Vague questions recover less, 8 of 10 after compaction and 7 of 12 in a new session.

Let the model ask precisely

Met: in a live session, the model followed an injected record id with memory_timeline and quoted the exact command and output from the previous session. SQL over the memory table answers questions such as "the last errors in this file".

Missed: whether the model searches depends on the model and on the prompt. A "don't run commands" instruction stopped it from searching memory at all. Headless sessions also need a permission rule for the MCP tools, which the installer now adds.

Scale to projects far beyond a context window

Met: at a million records (about 450 sessions of this size), a recall query takes 11.5 ms at the median, a full hook 17 ms, and the file holds 3.5 KB per record.

Missed: finding one conversation's evidence among generic filler gets harder as the store grows: recall@10 falls from 0.78 at 10,000 records to 0.52 at 100,000 and 0.45 at a million, with the static embedder. Filters on session, time and file, and better vectors, are what keep large stores precise.

Limitations

  • The benchmarks are chats, not coding sessions. LongMemEval and LoCoMo test personal-assistant memory. The coding evidence is one long session and a handful of live runs.
  • The session probes were written after seeing the answers. They favour distinctive terms, which is why the vague set exists; real questions sit between the two.
  • The gate was fitted on chat data. Its weights depend on the embedder and probably on the domain.
  • The static embedder trades quality for speed. BGE is better on paraphrases, but it costs about 50 ms per record on this CPU.
  • Hook latency assumes a pause between prompts. Back to back, a query waits for the previous write's background rebuild (44–53 ms).
  • Redaction is pattern-based. It catches common key and token formats, not every secret.

Next steps

  • A reranker behind the gate. A small cross-encoder scoring only the top candidates of prompts that pass the cheap gate.
  • Two-speed embeddings. Capture with the static model, and re-embed in the background with BGE when the machine is idle.
  • Fact-augmented keys. One cheap model call per turn writes the turn's decisions and facts into the episode card's index text. LongMemEval reports about +9% recall from this.
  • Time-aware queries. Turn "yesterday" or "before the refactor" into time or sequence filters, which Strata already evaluates.
  • Consolidation. Detect when a new decision supersedes an older one, instead of relying on the model to say so.
  • Shared project memory. One store per repository, synced between teammates' agents.
